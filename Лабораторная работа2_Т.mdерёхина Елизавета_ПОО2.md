Фрагмент для создания таблицы invoice: 
```sql
-- -----------------------------------------------------
-- Table `firstModel`.`invoice`
-- -----------------------------------------------------
CREATE TABLE IF NOT EXISTS `firstModel`.`invoice` (
  `idinvoice` INT NOT NULL AUTO_INCREMENT,
  `userid` INT NOT NULL,
  `productid` INT NOT NULL,
  `cost` DECIMAL(10,2) NOT NULL,
  PRIMARY KEY (`idinvoice`),
  INDEX `user_idx` (`userid` ASC) VISIBLE,
  INDEX `product_idx` (`productid` ASC) VISIBLE,
  CONSTRAINT `user`
    FOREIGN KEY (`userid`)
    REFERENCES `firstModel`.`user` (`id`)
    ON DELETE CASCADE
    ON UPDATE CASCADE,
  CONSTRAINT `product`
    FOREIGN KEY (`productid`)
    REFERENCES `firstModel`.`product` (`idproduct`)
    ON DELETE CASCADE
    ON UPDATE CASCADE)
ENGINE = InnoDB;
```

За создание таблицы orders отвечает следующий фрагмент запроса:
```sql
-- -----------------------------------------------------
-- Table `mydb`.`orders`
-- -----------------------------------------------------
CREATE TABLE IF NOT EXISTS `mydb`.`orders` (
  `id` INT NOT NULL AUTO_INCREMENT,
  `shop_id` INT UNSIGNED NOT NULL,
  `product_id` INT NOT NULL,
  `fio` INT NOT NULL,
  `date` DATE NULL,
  `quantity` INT NULL,
  `tel` VARCHAR(100) NULL,
  `confirm` TINYINT NULL,
  UNIQUE INDEX `id_UNIQUE` (`id` ASC) VISIBLE,
  PRIMARY KEY (`id`, `shop_id`, `product_id`, `fio`),
  INDEX `order_to_delivery_idx` (`fio` ASC) VISIBLE,
  INDEX `order_to_products_idx` (`product_id` ASC) VISIBLE,
  INDEX `shop_to_order_idx` (`shop_id` ASC) VISIBLE,
  CONSTRAINT `order_to_delivery`
    FOREIGN KEY (`fio`)
    REFERENCES `mydb`.`deliveries` (`fio`)
    ON DELETE NO ACTION
    ON UPDATE NO ACTION,
  CONSTRAINT `order_to_products`
    FOREIGN KEY (`product_id`)
    REFERENCES `mydb`.`prosucts` (`id`)
    ON DELETE NO ACTION
    ON UPDATE NO ACTION,
  CONSTRAINT `shop_to_order`
    FOREIGN KEY (`shop_id`)
    REFERENCES `mydb`.`shops` (`id`)
    ON DELETE NO ACTION
    ON UPDATE NO ACTION)
ENGINE = InnoDB;
```

Так как на всех моих связях ON DELETE было выставлено NO ACTION, то СУБД просто не даёт удалить родительские записи, пока к ним прикреплены дочерние. Но если бы выставлено было CASCADE то при удалении родительской записи все связанные с ней дочерние записи удалились бы автоматически.
